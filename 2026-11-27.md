## monero (core): 16 PRs merged

Two merge batches (24 and 25 Nov). Highlights:

- **`getblocks_by_height.bin` deprecated:** the wallet no longer needs it. `scan_tx` now orders transactions with `getblock` ([#11600](https://github.com/monero-project/monero/pull/11600)), timestamp-to-height lookups use block headers ([#11599](https://github.com/monero-project/monero/pull/11599)), and the endpoint is marked deprecated but still served for compatibility ([#11601](https://github.com/monero-project/monero/pull/11601), following a suggestion by kayabaNerve in [#10121](https://github.com/monero-project/monero/issues/10121)). The matching docs change was merged too (monero-docs [#439](https://github.com/monero-project/monero-docs/pull/439)).
- **RPC:** restricted-mode `get_output_histogram` now limits how many `amounts` one request can ask for. The PR says three clients sending long lists could push other requests on the port from about 1 ms to about 500 ms ([#11722](https://github.com/monero-project/monero/pull/11722)).
- **Wallet RPC / wallet:** the default `get_address` call marks used addresses in one pass, which the author measured as 1.45 s to 1.01 s on a synthetic wallet with 10,000 addresses ([#11757](https://github.com/monero-project/monero/pull/11757)); incoming pool payments now pick up a later double-spend flag ([#11761](https://github.com/monero-project/monero/pull/11761)); `get_version` exposes the daemon's network type to the wallet ([#11649](https://github.com/monero-project/monero/pull/11649)); `simplewallet` batches balances when listing accounts ([#11754](https://github.com/monero-project/monero/pull/11754)) and `export_transfers` gains a total column ([#11698](https://github.com/monero-project/monero/pull/11698)).
- **Memory safety:** a use-after-destruction fix in wallet2 block parsing ([#11716](https://github.com/monero-project/monero/pull/11716)) and `wipeable_string` now wipes its old contents on assignment ([#11715](https://github.com/monero-project/monero/pull/11715)).
- **Packaging / build:** the systemd unit restores the state and log directories and is sandboxed; the PR reports `systemd-analyze security` going from 9.0 "UNSAFE" to 1.7 "OK" ([#11517](https://github.com/monero-project/monero/pull/11517)). Also a consistent Asio thread backend on MinGW ([#11755](https://github.com/monero-project/monero/pull/11755)) and Boost `foreach` replaced ([#11765](https://github.com/monero-project/monero/pull/11765)).
- **Fuzzing:** two more OSS-Fuzz target sets from arthurscchan, for FCMP++ curve-tree processing and wallet refresh ([#11491](https://github.com/monero-project/monero/pull/11491), [#11508](https://github.com/monero-project/monero/pull/11508)). He opened several more this week (e.g. [#11788](https://github.com/monero-project/monero/pull/11788) FCMP++ verification, [#11793](https://github.com/monero-project/monero/pull/11793) wallet/daemon RPC).
- **New and open, worth watching:** selsta opened a batch of P2P and epee fixes, including removing DNS seed discovery ([#11795](https://github.com/monero-project/monero/pull/11795), closes the discussion in [#9695](https://github.com/monero-project/monero/issues/9695)), coordinating block span requests across peers ([#11791](https://github.com/monero-project/monero/pull/11791)), filtering RFC 6598 addresses from gossiped peer lists ([#11790](https://github.com/monero-project/monero/pull/11790)) and a TLS write-queue data race fix ([#11797](https://github.com/monero-project/monero/pull/11797)). Still open: the FCMP++ consensus PR [#11440](https://github.com/monero-project/monero/pull/11440), jeffro256's [#10916](https://github.com/monero-project/monero/pull/10916) and the anti-eclipse PR [#11707](https://github.com/monero-project/monero/pull/11707).
